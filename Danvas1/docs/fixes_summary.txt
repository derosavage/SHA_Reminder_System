3. UNICODE ENCODING CRASH
----------------------------------------------------------------
Problem: pybit error messages contain Unicode arrow "\u2192" which
         crashes Windows console with UnicodeEncodeError when logging
Fix:    Added ASCII-safe error message sanitization in 4 places:
        - test_connection()
        - get_position()
        - get_positions()
        - get_wallet_balance()
        Pattern: str(e).replace('\u2192', '->').encode('ascii','replace')
Result: No more logging crashes on Windows

4. MARKET DATA API PARSING (pybit v5 compatibility)
----------------------------------------------------------------
Problem: get_ticker() and get_klines() accessed response data at
         wrong path. pybit v5 wraps data in response['result']['list'],
         but code was checking response['list'] directly
Fix:    Both methods now extract data via:
        result = response.get('result', {})
        items = result.get('list') or response.get('list') or []
Result: Ticker and Kline data now properly parsed

5. ORDERBOOK DATA
----------------------------------------------------------------
Problem: get_orderbook() tried to access data['b'][0]['price'] but
         pybit v5 returns bid/ask as arrays: ["price", "size"]
         Also data is at response['result'] not response directly
Fix:    Changed data extraction to response.get('result', response)
        Changed access from data['b'][0]['price'] to data['b'][0][0]
        (only bid1/ask1 fixed; bid2-5, volumes still need array fix)
Result: Orderbook partially functional (bid1/ask1 working)
